| `Tags` | Multiple select; האפשרויות הידועות: "מבצע", "חדש" |
| `Show Zero` | Checkbox; האם להציג מוצר כשמלאי אפס |

שדה `Images` משמש לתמיכה במספר תמונות. דוגמה לערך:
`["/api/images/uuid.jpg","/api/images/uuid2.webp"]`

בטעינה, הקוד מנסה לפרסר את Images כמערך JSON. אם אין מערך תקין או שהוא ריק, הוא משתמש ב-`Image` כתמונה יחידה. בשמירה, ממשק הניהול מעדכן את Images כמחרוזת JSON וגם מעדכן את Image לתמונה הראשונה לצורך תאימות.

אין לשנות את שמות השדות או את סוגיהם בלי לעדכן את כל הקוד שקורא/כותב אותם.

#### כללי מוצר ותצוגה

- `Hidden=true`: המוצר מוסתר.
- `Stock`: מלאי מספרי; null/ריק משמעו מלאי לא מוגדר.
- `Show Zero=true`: מאפשר להציג מוצר גם כשהמלאי אפס, בהתאם ללוגיקת החנות.
- `On Sale=true` או תגית "מבצע": מסמן מבצע.
- `Tags`: האפשרויות הידועות "מבצע" ו"חדש".
- תמונות מוצגות בגלריה כאשר יש יותר מתמונה אחת.
- תצוגת תמונת מוצר ריבועית (1:1) משתמשת ב-contain כדי להימנע מחיתוך.

הקטגוריה בחנות מחושבת בקוד לפי מחיר. יש לקרוא את פונקציית הסיווג העדכנית ב-`index.html` לפני שינוי ספים. אין להניח ששדה Category הוא מקור האמת.

## 7. API פעיל ב-Cloudflare Pages

### 7.1 `GET /api/products`

- GET בלבד.
- קורא את כל הרשומות ב-Airtable בעמודים של עד 100.
- משתמש ב-`AIRTABLE_TOKEN`, `AIRTABLE_BASE_ID`, `AIRTABLE_TABLE_NAME`.
- מחזיר מערך מוצרים עם המפתחות:
  - `id`: Legacy ID אם קיים, אחרת Airtable record id.
  - `n`: שם.
  - `p`: מחיר.
  - `s`: מלאי או null.
  - `e`: אימוג'י.
  - `d`: תיאור.
  - `t`: מבצע.
  - `z`: Show Zero.
  - `h`: Hidden.
  - `img`: תמונה ראשונה.
  - `imgs`: מערך תמונות.
- כתובות ישנות מדומיין Netlify שמצביעות ל-`/img/` מומרות לנתיבים מקומיים.

### 7.2 `GET /api/winners`

- קורא את חמשת המספרים הפעילים מתוך `site.json` ואז את טבלת Lottery Winners ב-Airtable.
- מחזיר סטטוס רק לחמשת המספרים הפעילים; רשומות ישנות נשמרות אך אינן מוצגות.
- קורא את Lottery Winners.
- משתמש ב-`AIRTABLE_BASE_ID` וב-`WINNERS_AIRTABLE_TOKEN`.
- מחזיר `{ winners: [...] }` עם number, registered, firstName, lastName.
- מסנן למספרים המותרים בלבד.

### 7.3 `POST /api/winners`

- מאמת את המספר מול `site.json` בכל בקשה; שינוי המספרים באתר מתעדכן אוטומטית גם בבדיקת השרת.

Body:
`{ "number": "6", "firstName": "...", "lastName": "..." }`

הפעולה בודקת את המספר, השמות והאם הזכייה כבר נרשמה. הצלחה מעדכנת את Airtable: שמות ו-`Registered=true`.

קודי שגיאה חשובים: 400 נתונים לא תקינים, 404 מספר לא נמצא, 409 כבר נרשם, 503 תקלה בשירות.

### 7.4 ניהול מוצרים

כל הנתיבים הבאים דורשים Session מנהל תקף:
- `GET /api/admin/products`: קריאת מוצרים.
- `POST /api/admin/products`: יצירת מוצר.
- `PATCH /api/admin/products`: עדכון מוצר לפי recordId.
- `DELETE /api/admin/products`: בפועל מבצע soft-hide על ידי `Hidden=true`, לא מחיקה פיזית.

הכתיבה משתמשת ב-`AIRTABLE_WRITE_TOKEN`. קלט המוצר כולל name, price, stock, description, images או image, emoji, tags, onSale, showZero, hidden. הקוד מגביל עד 12 תמונות, עד 2,000 תווים לתיאור ועד 120 תווים לשם. המחיר והמלאי חייבים להיות מספרים לא שליליים; תמונות מתקבלות רק בכתובות HTTPS, בנתיב /img/ או בנתיב /api/images/.

שדה Category אינו נכתב על ידי עורך המוצרים.

### 7.5 העלאת תמונה

`POST /api/admin/upload`

- דורש Session מנהל ו-Origin תואם.
- מקבל FormData עם שדה `file`.
- פורמטים: JPEG, PNG, WEBP, GIF.
- גודל מרבי: 5MB לקובץ.
- נשמר ב-R2 עם UUID ושם קובץ הכולל סיומת.
- מחזיר `{ success: true, url: "/api/images/<key>" }`.

בממשק הניהול ניתן לבחור מספר קבצים; ה-Frontend מעלה אותם אחד אחרי השני, ומוסיף את הכתובות לרשימת תמונות המוצר. לאחר מכן יש לשמור את המוצר כדי לקשר את הכתובות לרשומה ב-Airtable.

### 7.6 הצגת תמונה

`GET /api/images/<uuid>.<extension>`

הפונקציה בודקת מבנה UUID וסיומת מותרת, קוראת מ-R2 ומחזירה את התמונה. הקבצים מקבלים Cache-Control ארוך ו-immutable.

```text
*הזמנת הרש-שופ*

שם מוצר × כמות = מחיר הרשקלים

שם מוצר נוסף × כמות = מחיר הרשקלים

מספר

שם המזמין

הערות המזמין
```

שורות השם וההערות הן אופציונליות: כל אחת מהן מתווספת להודעה רק אם השדה המתאים מכיל טקסט שאינו ריק לאחר הסרת רווחים. אם השדה ריק, גם הכותרת שלו אינה נכללת. שורות המוצרים והסכום נשארות תמיד.
